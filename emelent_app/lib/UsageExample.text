Key Design Decisions
1. Either Type (from dartz)
All use cases return Either<Failure, Success> which forces explicit error handling:

dart

final result = await loginUseCase(params);
result.fold(
  (failure) => handleError(failure),
  (session) => handleSuccess(session),
);
2. Validation in Use Cases
Business validation happens in use cases, not in UI or repository:

dart

// Use case validates before calling repository
final emailError = Validators.email(params.email);
if (emailError != null) {
  return Left(ValidationFailure(...));
}
3. Equatable Params
All parameter classes extend Equatable for easy comparison and testing:

dart

class LoginParams extends Equatable {
  @override
  List<Object?> get props => [email, password];
}
4. Separation of Concerns
Entity: Pure data, no dependencies
Repository: Contract only, no implementation
Use Case: Single responsibility, one action
